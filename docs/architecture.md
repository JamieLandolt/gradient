# Gradient — Architecture

> Companion to `Gradient_SRS_Master.md` §2.4. Updated as phases land.

## Guiding principle

Strict separation between **deterministic logic that must be correct** and
**language-model assistance**:

- Grade arithmetic, GPA/WGPA, prerequisite satisfaction, and plan validity are
  computed by plain code in the backend's domain engines. No LLM is ever involved
  (FR-3.3.6, FR-3.6.7).
- LLM-backed features (ECP extraction, recommendations, study plans, assistant,
  embeddings) sit behind provider interfaces (`app/providers/interfaces.py`).
  In v1 every provider is a **deterministic mock** selected by `AI_PROVIDER=mock`.
- Any grade or prerequisite fact cited by an AI artefact is supplied by the
  deterministic engines, never generated by a model.

## Layers

```
React SPA (Vite)  ──HTTPS/JSON──▶  FastAPI backend  ──service role──▶  Supabase
     │                                  │                               Postgres + pgvector
     └──supabase-js (auth only)─────────┼──────────────────────────────  Auth / Storage
                                        ▼
                       domain engines (calculation, planning)
                       providers (mock extraction/embeddings/recs/plans)
```

- **Frontend** authenticates directly with Supabase Auth (email + password) and
  sends the access token as a Bearer header to the API. All data access goes
  through the API; supabase-js is used for auth/session only.
- **Backend** is stateless (NFR-5.2.1). It verifies Supabase JWTs locally
  (JWKS with HS256 fallback), then acts through repositories using the
  service-role client. Because the service role bypasses RLS, **every
  repository method that touches student data filters by the authenticated
  `user_id`** — this is a hard convention, enforced by API tests asserting
  cross-user access returns 404.
- **Database**: RLS enabled on all tables. Catalogue tables are public-read;
  student-owned tables are `auth.uid() = user_id`. Views (if any) are created
  `with (security_invoker = true)`.

## Module map (backend)

| Path | Responsibility |
| --- | --- |
| `app/domain/calculation/` | standing, required marks, hurdles, GPA — pure, frozen dataclasses |
| `app/domain/planning/` | prerequisite AST evaluation, dependency graph, scheduler, dual degree |
| `app/providers/` | Protocol interfaces + env-selected implementations (mock in v1) |
| `app/repositories/` | one module per aggregate; the only place SQL/Supabase calls live |
| `app/services/` | orchestration between repositories, engines, and providers |
| `app/api/` | thin routers; Pydantic validation; standard response envelope |

## Response envelope

Every endpoint returns `{"success": bool, "data": …, "error": str|null, "meta": …}`
(`app/core/envelope.py`); errors are normalised by `app/core/errors.py`.
